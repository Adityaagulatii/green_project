# Polyglot plan: 17×9 Tetris → building-scale simulator

**Goal:** the same game, and the same building simulator, built four times: **Python → Hy → Clojure/ClojureScript → Scheme (Guile 3)**. Every rebuild is held to a language-neutral, versioned `SPEC.md`, and checked against the original Python.

Every step delivers the same four things for its language:

1. **Implementation.** A *pure* engine: game state + input events → next state + frame. There is no I/O in the core.
2. **Simulator + visualization.** A headless display model of the building, plus a renderer in that language.
3. **Tests.** Property-based tests in the language's idiom, plus the shared **conformance traces**.
4. **Spec update + seal.** Clarifications and revisions found during the rebuild go into `SPEC.md`, and the result is sealed.

## Determinism: what makes traces possible

The original uses `np.random.shuffle` and wall-clock busy-waits, so it isn't reproducible. The spec therefore defines a **conformance mode**:

- **Randomness.** The 7-bag is shuffled with a spec-defined PRNG (e.g. SplitMix64 or xorshift32, with its exact algorithm written in SPEC.md) and a Fisher–Yates procedure. The seed is part of the trace.
- **Time.** Time is a sequence of logical **frames at 30 FPS**. Inputs are events `(frame, action, down?)`, applied in order at frame boundaries. Gravity, DAS, ARR and DCD are expressed in frames. The legacy "gravity × 2 at half FPS" and the subtick loop are mapped explicitly in the spec.
- **Frame digest.** SHA-256 of the canonical row-major `R,G,B` bytes of the 17×9 display frame. Each trace stores digests for every frame, or for every *k* frames plus the final one.
- **Quirks are part of the contract.** Legacy behaviours such as the 180° kick arithmetic, CCW resetting DCD, scoring `100 × (lines ÷ 10 + 1)`, and the level-target formula are specified as-is and marked `QUIRK`. A revision may change them, but only through the process below.

## Seal and rebuild protocol

1. **Seal.** Bump the `Spec vN` header in `SPEC.md` and add a changelog entry. Record `sha256(SPEC.md)`, `sha256` of the trace set, and the implementation commit in `spec/SEALS.md`, then create an annotated tag `spec-vN-<lang>`.
2. **Rebuild.** A new implementation must pass **all** traces of the latest sealed spec *before* proposing any spec change.
3. **Classify each change** the rebuild finds:
   - A **clarification** (the wording was ambiguous, behaviour unchanged) is a patch-level note.
   - A **revision** (behaviour changes) must regenerate the traces, update every earlier implementation or record why it diverges, and keep the Python legacy differential result on record.
4. **Look back at the original.** Every seal re-runs the Python differential suite against `impl/python/legacy/`. That keeps "what the original actually did" one command away.

## Simulator scope (all languages)

- **Display contract:** `Display.send(frame)`, `makeframe()`, a 17×9 `Frame` of `Color` (RGB, 0–255 each), at 30 FPS.
- **Building model:** 153 windows. The row→floor and column→bay mapping is **TBD**: confirm the simulator's layout at the hack on Sep 13, then put it in the spec.
- **Headless sink:** records frames and timing. Renderers read from it. Idle, countdown, line-clear and game-over animations are all just frame streams.
- **Embodied-AI hooks** (from the hack brief): a frame producer can be the game *or* a behaviour (gestures, mood colors, a world transition). The spec reserves an `Animation` interface for these.
