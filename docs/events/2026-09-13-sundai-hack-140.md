## About

MIT's Green Building Tetris installation is back: **153 individually lit windows across a 21-story tower, running the game at 30 FPS.** This hack takes the existing codebase off the shelf and asks a different question: *what does it look like to make this building a body?*

Teams work from the live Tetris repo and its display API to prototype ways of turning the Green Building into an embodied AI. That means something that can sense, respond, and express itself through light across an entire building facade. The event is hardware friendly, so bring your own hardware if you want to hack with it.

A **simulator** will be available on Sunday to test concepts. On **September 29**, the actual Green Building becomes a live embodied-AI demo. The strongest concepts from the hack are expected to carry through to that install, pending MIT approval.

### Possible directions
- The building responds to people or activity below with gesture-like light patterns.
- Colors and shapes shift to reflect mood, sound, or conversation.
- A "world transition" effect, as if the building is carrying you somewhere new.
- Any other interaction that treats the window grid as a physical, embodied interface.

## Notes for our team
- **The contract is Python.** `utilities/display.py` defines `Display` (`send(frame)`, `makeframe()`), and a `Frame` is a 17×9 numpy grid of `Color`. 17 × 9 = 153, the building's window count. Anything that can produce frames for that API can drive the facade.
- **This fork is going polyglot** (see [`docs/POLYGLOT-PLAN.md`](../POLYGLOT-PLAN.md)). The original Python becomes one implementation. The game is then rebuilt as Python → Hy → Clojure/ClojureScript (web simulator) → Guile 3. Each step ships an engine, a simulator/visualization and property-based tests, and seals a language-neutral `SPEC.md`. Shared conformance traces keep every rebuild honest against the original Python.
- **An embodied behaviour is just a frame producer.** Anything that yields a `Frame` at 30 FPS and calls `display.send(frame)` can run on the facade. The game loop is one such producer; sensing → mood → light patterns would be another.
- **To confirm on the day:** how the simulator is delivered (a `Display` subclass or a network protocol?), its input and sensor feeds (camera, mic, footfall?), and the frame-rate and brightness limits for the live install.
